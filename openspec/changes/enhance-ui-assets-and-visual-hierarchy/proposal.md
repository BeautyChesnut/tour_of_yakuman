# Proposal: 优化 UI 素材与视觉层级

## 背景

`optimize-scoring-workbench-ui` 已经把算点页从长表单改造成三段式工作台，核心录入流程也完成了微信开发者工具验证。下一阶段的问题不再是结构，而是“看起来仍然像文字表单”：麻将牌、方位、操作按钮、桌面区域和结果页都需要更强的视觉表达，才能在真实线下牌桌环境中快速扫读。

## 目标

- 用稳定、可复用的麻将牌视觉素材替换手牌、宝牌、鸣牌中的纯文字牌面。
- 使用 gpt-image 生成麻将牌、方位、状态、按钮和桌面视觉素材，并将筛选后的素材随小程序离线打包。
- 为方位、立直、记录、回退、重置、确认等高频信息和操作提供统一图标表达。
- 优化虚拟牌桌视觉，让四家方位、亲家、赢家、放铳者、立直状态更容易识别。
- 优化结果页视觉层级，让役种、番符、支付、点数变化和点差更容易扫读。
- 建立小程序内可维护的资产组织方式，避免素材散落在页面样式中。

## 非目标

- 不改变当前算点规则、结算模型和输入数据结构。
- 不新增拍照识别、在线素材下载或后台能力。
- 不引入复杂主题系统；第一版只沉淀一套默认视觉风格。
- 不做完整品牌 VI 设计，只做服务于算点效率的应用内素材与层级优化。

## 范围

- 牌面素材：万、筒、索、字牌、赤五，覆盖输入格、牌盘和摘要展示。
- UI 图标：方位、立直、记录、回退、重置、清空、确认、警示。
- 桌面视觉：桌布、桌心、玩家区状态、亲家/赢家/放铳/立直标识。
- 结果页：主结算结果、役种列表、番符、支付明细、四家点数变化、点差。
- 生成流程：通过 gpt-image 生成候选素材，人工筛选后切片、压缩并纳入 `miniprogram/assets/`。
- 资产规范：文件命名、目录、尺寸、颜色、深浅背景适配和小程序包体控制。

## 风险

- 牌图素材如果过多或尺寸过大，会增加小程序包体。
- gpt-image 生成的素材可能存在风格不一致、文字不稳定或细节噪点，需要人工筛选、必要时重生成。
- 纯图片牌面在不同屏幕密度下可能不如文本清晰，需要控制导出尺寸并保留文本 fallback。
- 视觉增强不能牺牲输入密度，尤其是手牌 14 格和宝牌 8 格仍需要横向不溢出。
- 结果页信息量大，过度装饰会降低扫读效率。

## 验收信号

- 用户在手牌、宝牌、鸣牌区域能直接看到麻将牌视觉，而不主要依赖文字编码。
- 牌桌区能一眼区分亲家、赢家、放铳者和已立直玩家。
- 结果页能优先看到“赢了多少、谁付给谁、结算后点数如何变化”。
- 小屏宽度下牌格不溢出，文本不遮挡素材。
- 素材文件集中管理，后续替换图标或牌面不需要改业务逻辑。
