## ADDED Requirements

### Requirement: 系统使用统一牌面视觉展示麻将牌

系统 SHALL 在手牌、和牌张、宝牌、里宝牌、鸣牌和牌盘中使用统一的麻将牌视觉组件或等价样式展示牌面，而不是主要依赖内部牌编码文本。

#### Scenario: 展示数牌

- **WHEN** 用户查看任一牌面输入区域
- **THEN** 系统用统一牌面样式展示万、筒、索数牌，并保持不同花色可区分

#### Scenario: 展示字牌

- **WHEN** 用户查看东、南、西、北、白、发、中
- **THEN** 系统用统一牌面样式展示字牌，并保持小尺寸下文字清晰

#### Scenario: 展示赤五

- **WHEN** 用户在手牌、和牌张、鸣牌或牌盘中查看赤五
- **THEN** 系统用区别于普通五的视觉标识展示赤五

#### Scenario: 空牌格

- **WHEN** 某个牌格尚未输入
- **THEN** 系统展示轻量占位状态，不影响整行牌格尺寸

### Requirement: 系统使用统一状态标识展示牌桌状态

系统 SHALL 为亲家、立直、听牌、赢家和放铳者提供统一状态标识，并在牌桌区和结果页中复用。

#### Scenario: 展示亲家

- **WHEN** 用户查看牌桌区
- **THEN** 系统在当前亲家玩家区展示亲家标识

#### Scenario: 展示立直

- **WHEN** 某家已被标记为立直
- **THEN** 系统在该玩家区展示立直标识，并保持点数可读

#### Scenario: 展示赢家和放铳者

- **WHEN** 当前事件为荣和
- **THEN** 系统分别用不同状态标识展示赢家和放铳者

#### Scenario: 展示流局听牌

- **WHEN** 当前事件或结果为荒牌流局
- **THEN** 系统用听牌状态标识展示听牌玩家

### Requirement: 系统优化虚拟牌桌视觉层级

系统 SHALL 优化牌桌区背景、桌心、玩家区、方位、点数和点差层级，使用户能快速识别当前局况和四家状态。

#### Scenario: 查看牌桌

- **WHEN** 用户停留在算点工作台
- **THEN** 系统以桌面视觉承载四家状态，而不是普通列表式卡片

#### Scenario: 查看桌心

- **WHEN** 用户查看牌桌中心
- **THEN** 系统展示当前局况摘要，且不与四家点数争夺主视觉层级

#### Scenario: 小屏展示

- **WHEN** 用户在小屏设备查看牌桌区
- **THEN** 系统保持方位、点数、点差和状态标识不重叠

### Requirement: 系统优化全局操作图标表达

系统 SHALL 为记录、回退、重置、清空、确认和警示等高频操作提供统一图标或图标化样式，并保留中文标签。

#### Scenario: 查看全局操作

- **WHEN** 用户查看场况区操作按钮
- **THEN** 系统展示图标化按钮，并保留可读中文标签

#### Scenario: 查看危险操作

- **WHEN** 用户查看重置复位等高风险操作
- **THEN** 系统使用危险态视觉，但仍要求二次确认

#### Scenario: 清空当前格

- **WHEN** 用户在牌面输入面板查看清空当前格入口
- **THEN** 系统用统一图标化样式展示该操作

### Requirement: 系统优化结果页视觉层级

系统 SHALL 在结果页中优先展示主结果、支付摘要和四家点数变化，再展示役种、宝牌、符数明细和点差信息。

#### Scenario: 展示和牌结果

- **WHEN** 用户完成荣和或自摸结算
- **THEN** 系统优先展示主结果、番符和支付摘要

#### Scenario: 展示四家点数变化

- **WHEN** 用户查看结果页
- **THEN** 系统清晰展示每家点数增减、结算后点数和当前最高状态

#### Scenario: 展示役种和符数

- **WHEN** 用户查看详细算点依据
- **THEN** 系统展示役种、宝牌和符数明细，但视觉层级低于主结果和支付摘要

#### Scenario: 展示流局结果

- **WHEN** 用户完成荒牌流局结算
- **THEN** 系统优先展示听牌者、荒牌罚符、连庄或轮庄、本场变化和供托保留

### Requirement: UI 素材集中管理且不依赖网络

系统 SHALL 将核心 UI 素材、图标样式或牌面组件集中管理，并保证核心算点 UI 在离线状态下可完整展示。素材 MAY 通过 gpt-image 生成，但 MUST 作为本地小程序资源打包，不得在核心算点流程中运行时依赖网络生成或下载。

#### Scenario: 离线打开小程序

- **WHEN** 用户在无网络状态下打开算点页
- **THEN** 系统仍能展示麻将牌视觉、状态标识和操作图标

#### Scenario: 后续替换素材

- **WHEN** 开发者需要替换牌面或图标素材
- **THEN** 应能通过集中组件、样式或资产目录替换，而不需要修改算点业务逻辑

#### Scenario: 使用生成素材

- **WHEN** 项目采用 gpt-image 生成的牌面、状态或图标素材
- **THEN** 系统将筛选、压缩后的素材放入本地资产目录，并通过组件或映射表引用

#### Scenario: 生成素材缺失

- **WHEN** 某张牌或某个图标的生成素材缺失
- **THEN** 系统应使用文本或 CSS fallback 展示可读内容，而不是显示空白或破图
