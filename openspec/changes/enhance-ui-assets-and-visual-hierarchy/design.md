# Design: UI 素材与视觉层级优化

## 设计原则

- **先识别，后美化**：素材的第一职责是让用户在牌桌旁更快确认输入和结果。
- **高密度但不拥挤**：手牌、宝牌、鸣牌仍要保持横向紧凑，素材不能撑高页面。
- **业务状态视觉化**：亲家、立直、赢家、放铳者、流局听牌等状态要有稳定视觉标识。
- **资产可替换**：页面组件依赖统一的 tile/icon 映射，不直接硬编码素材路径。
- **离线可用**：所有核心素材随小程序包发布，不依赖网络加载。

## 素材策略

### 素材生成来源

本 change 决定允许并优先使用 gpt-image 生成 UI 素材。生成范围包括：

- 麻将牌面素材：万、筒、索、字牌、赤五，以及空牌格占位。
- 方位与状态素材：东、南、西、北、亲、立、听、和、铳等状态章。
- 操作图标：记录、回退、重置、清空、确认、警示。
- 桌面视觉：桌布纹理、桌心装饰、结果页主视觉辅助元素。

生成后的素材 MUST 经过人工筛选、裁切、压缩和命名后进入小程序包，不在运行时调用 gpt-image，也不依赖网络加载。

建议生成流程：

```text
prompt 草案
  -> gpt-image 生成候选图
  -> 人工筛选统一风格
  -> 切片/透明背景/压缩
  -> 放入 miniprogram/assets/
  -> 组件通过映射表引用
```

### 牌面素材

已验证整套牌面一次性生成不稳定，当前采用 `references/mjui.png` 牌面素材切片方案，并保留文本 fallback：

| 方案 | 优点 | 风险 | 建议 |
| --- | --- | --- | --- |
| `mjui.png` 切片牌面 | 牌义准确、包含标准 1s 鸟牌和全红赤五 | 依赖外部素材质量 | 当前采用 |
| gpt-image 生成空白牌胚 | 牌体真实、牌义由本地保证 | 需要本地叠加内容 | 已弃用，不进入小程序包 |
| gpt-image 生成整套 PNG 牌面 | 视觉统一、质感好、离线可用 | 牌种错漏、文字不稳定 | 仅保留为风格参考 |
| PNG 雪碧图 | 请求少、管理集中 | 切图坐标维护成本 | 可选，如果单文件更稳 |
| CSS + 文本 fallback | 包体小、清晰 | 视觉质感弱 | 必须保留兜底 |

第一版建议实现 `TileFace` 组件或等价渲染函数：

- 默认使用从 `references/mjui.png` 切出的完整单张牌面 PNG。
- 素材缺失时使用 CSS + 文本 fallback。
- 数牌、字牌、赤五需要统一尺寸比例，支持 compact 和 normal 两种展示。
- 赤五直接依赖切片素材中的全红外观，内部仍使用现有 `red5m/red5p/red5s`，不再额外叠加红点。
- 输入格中的空状态保持轻量占位，不使用大面积灰块。

### 方位与状态素材

方位与状态素材可以使用 gpt-image 生成，但形态上仍建议是“短字章 + 小图形”的组合，避免小尺寸不可读：

- 东/南/西/北：圆形或方形方位章。
- 亲家：在东家或当前亲家玩家区显示“亲”标记。
- 立直：红色细长立直棒或“立”小章。
- 赢家：金色或浅黄状态边。
- 放铳者：浅红状态边。
- 流局听牌：在流局结果或桌面状态中使用“听”小章。

### 操作图标

按钮图标可以通过 gpt-image 生成统一风格素材。需要覆盖：

- 记录。
- 回退。
- 重置。
- 清空当前格。
- 确认结算。
- 警示/错误。

图标按钮必须保留中文可读标签，避免用户只看符号不明白操作含义。若生成图标在小尺寸下不清晰，应退回 CSS 图标或文本符号。

## 页面设计

### 牌桌区

目标是让桌面更像“状态总览”，而不是普通卡片。

```text
-----------------------------+
|          北 25000          |
|          -1200             |
|                             |
| 西 24800   东一局   东 26200|
| -1400      1本场   当前最高 |
|                             |
|          南 25000          |
|          -1200             |
+-----------------------------+
```

视觉调整：

- 桌面背景保持绿色，但减少过强阴影和厚重边框。
- 桌心展示局况摘要，不重复展示过多说明。
- 玩家区使用方位章、点数、点差三层结构。
- 亲家、赢家、放铳者、立直状态用边框/角标表达，不改变布局尺寸。

### 牌面输入区

牌面输入要复用同一视觉：

- 手牌：14 个牌格仍在一行，牌面组件需要支持极小宽度。
- 宝牌：8 个牌格一行，前 4 宝牌、后 4 里宝牌可用小标签或分隔线区分。
- 鸣牌：2 行 × 2 组，每组 4 个牌格，自动推断状态文字保持短。
- 牌盘：四行牌面按钮，不横向溢出。

### 结果页

结果页信息层级建议：

1. 顶部主结果：满贯/跳满/役满、番符、和牌方式。
2. 支付摘要：谁向谁支付多少，自摸时突出亲/子支付。
3. 四家点数变化：每家 `+/-`、结算后点数、当前排名。
4. 役种与宝牌：先展示役种，再展示宝牌番。
5. 符数明细：默认可折叠或靠后展示。
6. 点差：作为结果页底部比较信息。

流局结果页应改成另一种层级：

1. 荒牌流局。
2. 听牌者。
3. 荒牌罚符支付。
4. 连庄/轮庄与下一局本场。
5. 四家点数变化。

## 资产组织

建议目录：

```text
miniprogram/
  assets/
    icons/
    tiles/
    table/
    result/
  components/
    tile-face/
    state-badge/
```

`assets/tiles/` 存放生成后的牌面素材或牌面雪碧图；`assets/icons/` 存放操作图标和状态章；`assets/table/` 存放桌面相关素材；`assets/result/` 存放结果页辅助素材。所有素材需要有命名规范和来源说明。

## 组件边界

### TileFace

职责：把内部牌编码渲染成统一牌面。

输入：

- `tile?: Tile`
- `size?: compact | normal`
- `active?: boolean`
- `winning?: boolean`
- `fallbackLabel?: string`

输出：

- 不改变业务数据。
- 优先展示生成素材；素材缺失时使用文本 fallback。
- 只负责视觉展示，不改变业务数据。

### StateBadge

职责：渲染亲、立、听、和、铳等短状态。

输入：

- `type: dealer | riichi | tenpai | winner | discarder`
- `label?: string`

### IconButton

职责：统一图标按钮尺寸、触控区域、危险态和禁用态。

输入：

- `icon`
- `label`
- `variant`

## 实施策略

建议顺序：

1. 编写 gpt-image 生成提示词，生成牌面、状态章、操作图标、桌面和结果页候选素材。
2. 筛选、切片、压缩素材，并放入 `miniprogram/assets/`。
3. 建立 `TileFace` 或等价牌面渲染能力，先替换输入格和牌盘。
4. 建立状态章和操作图标样式，替换场况区和牌桌区按钮/标识。
5. 调整牌桌视觉，不改变现有状态和事件逻辑。
6. 调整结果页结构和样式，不改变结果数据。
7. 做小屏验收，重点检查手牌 14 格、宝牌 8 格、鸣牌 2×2、结果页长文本。

## 待验证问题

- 微信小程序原生组件是否适合抽出 `tile-face` 自定义组件，还是先在页面内用样式类实现更稳。
- gpt-image 生成的麻将牌在小尺寸下是否足够清晰。
- 生成素材中的汉字是否稳定；如果不稳定，字牌和状态章需要改用本地文字叠加。
- 图片素材总大小是否满足小程序包体预期。
- 结果页符数明细是否需要折叠；第一版可以先通过视觉顺序弱化。
