## Context

局势分析领域模块目前默认遍历东南西北四席，并把正式结算的 `playerCount` 固定为 4。详情页同样固定展示三个升位目标、跌四风险及四个视角。与此同时，本地算点桌面已经使用 `getActiveSeats(playerCount)` 支持东、南、西三席的三麻结算，因此可以在不复制规则引擎的前提下扩展分析。

## Goals / Non-Goals

**Goals:**

- 让本地三麻复用现有局势分析入口与详情页。
- 所有排名、支付和流局推演仅使用当前玩法的有效座位。
- 保持旧四麻快照与现有四麻结果兼容。
- 通过领域测试覆盖三麻升位、末位风险、自摸、立直、流局和终局阶段。

**Non-Goals:**

- 不开放在线三麻房间。
- 不实现北家参与排名、缺失北家补偿或其他平台特有三麻支付规则。
- 不增加牌河、向听或概率型 AI 分析。

## Decisions

1. 分析输入增加可选 `playerCount`，缺省值为 4；新快照显式记录人数。这样旧快照仍按四麻读取，同时新逻辑可统一通过 `getActiveSeats` 获取有效座位。
2. 将末位风险抽象为“跌至最后一位”，三麻最后一位为第三位，四麻为第四位。保留旧四麻分析函数作为兼容入口，页面改用通用末位分析。
3. 荣和与自摸候选仍复用现有合法符番点数枚举，但三麻自摸合计只统计两名实际付款者；正式结算继续由 `applyHandPaymentSettlement` 完成本场和供托处理。
4. 荒牌流局直接向 `applyDrawSettlement` 传入快照玩家人数，确保三麻 3000 点罚符只在东南西之间分配。
5. 页面根据人数动态生成目标页签和有效座位。三麻显示“升至第一位”“升至第二位”“跌三风险”，四麻维持现状。
6. 三麻默认半庄终局为南三局；同点破平顺序从全局东南西北顺序中过滤有效座位得到东南西。

## Risks / Trade-offs

- [三麻规则存在平台差异] → 明示本工具采用当前项目既有的无北家补偿支付与东南西同点顺序，实际终局仍以现场规则为准。
- [旧快照没有玩家人数字段] → 读取时缺省为四麻，并在快照校验中接受该兼容情况。
- [页面原有命名绑定第四位] → 引入通用末位视图文案，避免三麻出现第四位或北家。
