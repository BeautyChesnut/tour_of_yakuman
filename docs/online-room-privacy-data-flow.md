# 在线房间隐私与数据流

本文档说明 2.0 在线房间模式涉及的数据、存储位置和隐私边界。单机算点模式仍在本地运行，不依赖后台服务。

## 数据范围

在线房间模式会使用微信云开发保存以下数据：

- `openid`：微信登录后获得的稳定用户身份，用于创建房间、加入房间和校验房主权限。
- 展示信息：用户主动提供或本地玩家名生成的 `displayName`，以及可选 `avatarUrl`。
- 房间信息：房间 ID、房间码、房主 openid、东南西北座位绑定、房间状态、创建时间、更新时间和过期时间。
- 共享算点状态：当前局况、四家点数、手牌、和牌张、鸣牌、宝牌、场面番型、立直/听牌状态、状态版本号。
- 结算记录：本局事件、输入快照、算点结果、点数变化、结算后点数、创建者和创建时间。

在线房间不会保存以下数据：

- 房主当前打开的弹层。
- 当前选中的牌格焦点。
- 页面临时错误提示。
- 客户端诊断日志不会保存完整 openid、昵称、头像、房间码、手牌或点数状态。

重测期间，小程序会在在线功能失败或发生未处理异常时自动发送最小诊断事件。事件仅包含小程序版本、运行环境、功能动作、错误码、云托管请求编号、耗时、网络类型和发生时间，用于在现有云托管运行日志中定位问题，不建立独立用户画像，也不要求用户填写反馈。
- 本地确认弹窗状态。
- 聊天、语音、实时出牌或完整牌谱回放。

## 数据流

1. 用户点击在线房间入口后，小程序调用 `wx.login`。
2. 小程序调用 `login` 云函数，云函数从微信上下文获取 openid，并创建或更新用户记录。
3. 房主调用 `createRoom` 云函数，云函数创建房间、座位绑定和初始共享算点状态。
4. 成员调用 `joinRoom` 云函数，云函数校验房间有效、未满员，并绑定空座位或返回已有座位。
5. 房主编辑共享算点数据后，小程序调用 `updateRoomState` 云函数；云函数校验 `openid === ownerOpenId` 和状态版本号。
6. 房主确认结算后，小程序调用 `confirmSettlement` 云函数；云函数写入房间结算记录并更新四家点数和版本号。
7. 房主可在成员面板选择另一名已入座成员并调用 `transferRoomOwner`；服务端校验双方身份后更新房主，原房主随即变为只读成员。
7. 成员通过刷新房间状态读取同一份共享状态和结算结果。

## 权限边界

- openid 是房间权限判断的唯一身份凭据。
- 昵称、头像和座位名只用于展示，不能作为权限判断依据。
- 非房主即使绕过前端 UI 调用云函数，后端也必须拒绝修改共享状态和确认结算。
- 非房主不得转让房主；房主也不得转让给自己或未入座用户。
- 房间状态使用版本号保护，过期版本不能覆盖最新状态。

## 保留与清理

- 房间数据包含 `expiresAt`，过期后不允许新成员加入。
- 第一版在线房间不实现自动清理任务；后续可通过云函数定时清理过期房间和结算记录。
- 若在线功能需要临时下线，可以隐藏在线入口，单机算点不受影响。

## 单机模式

单机模式不上传用户数据，不读取 openid，不依赖网络请求完成算点。玩家名、点数和最近记录仍按本地页面状态和本地存储处理。
