# UI 视觉静态验证记录

本文档记录 `enhance-ui-assets-and-visual-hierarchy` 的静态验证结果。微信开发者工具内的真机/模拟器验证仍需人工完成。

## 牌面输入

- 手牌与和牌张保持 14 格单行：`.hand-strip` 使用 `repeat(14, minmax(0, 1fr))`，单格固定高度 `54rpx`，内容由 `tile-face` 自适应。
- 宝牌与里宝牌保持 8 格单行：`.dora-slot-row-combined` 使用 `repeat(8, minmax(0, 1fr))`，单格固定高度 `58rpx`。
- 鸣牌保持 2×2 分组：`.meld-grid` 使用双列，每组 4 格，单格固定高度 `52rpx`。
- 牌盘万/索/筒行支持赤五：手牌与鸣牌牌盘使用 `handTileRows`，每行 10 格；宝牌牌盘使用 `doraTileRows`，每行 9 格且不含赤五。
- 空格、选中态、和牌张高亮由 `tile-face` 内部状态统一呈现。

## 牌桌触控

- 玩家点击区域仍绑定在 `.seat-card` 上，状态章只作为内部展示，不拦截业务逻辑。
- `.seat-card` 保持固定宽度 `190rpx`、最小高度 `120rpx`，触控区域大于常见移动端最小触控建议。
- 立直切换仍由 `handleToggleRiichi` 处理，新增视觉状态不改变数据流。

## 结果页长文本

- 主结果、支付摘要、四家点数已前置。
- 支付摘要单独成块，长文本在块内自然换行。
- 四家点数使用固定列结构，点数增减、结算后点数和当前最高标识分列展示。
- 役种、宝牌、符数和点差置于主结果之后，降低长列表对首屏判断的干扰。
