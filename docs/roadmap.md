# 项目路线图

## 项目愿景

开发一款微信小程序，帮助线下立直麻将玩家在最终和牌时，通过拍照上传和人工确认，计算番数、符数、役种和各家点数收支。

目标用户是已经熟悉立直麻将玩法，但不太擅长番符和点数计算的玩家。

## MVP 范围

第一版聚焦四人立直麻将，以及可靠的辅助算点流程。

### 核心用户流程

1. 在简单的模拟麻将桌视图中设置当前局况。
2. 上传或拍摄和牌照片。
3. 查看并修正识别出的牌面。
4. 补充照片无法判断的和牌条件。
5. 计算并展示番数、符数、役种和点数收支。

### 牌桌局况

- 当前局数，例如东一局、南三局。
- 本场数。
- 立直供托数量。
- 亲家方位。
- 和牌者方位。
- 荣和时的放铳者方位。
- 自摸或荣和。
- 可选的各家当前点数。

### 算点结果

- 最终牌值，例如满贯、跳满，或精确的番符点数。
- 总番数。
- 总符数。
- 役种列表及对应番数。
- 符数明细。
- 各家支付或收入明细。
- 本场和立直供托的调整。

## 阶段计划

### 阶段 1：产品定义

- 明确 MVP 算点规则和非目标。
- 决定第一版默认的四人立直麻将规则。
- 定义模拟麻将桌的交互方式。
- 定义手动确认牌面和补充和牌条件的流程。
- 创建 OpenSpec proposal 和需求文档。

### 阶段 2：算点引擎

- 实现手牌数据结构。
- 实现役种判断。
- 实现符数计算。
- 实现荣和和自摸的点数计算。
- 为常见牌型、边界情况和役满牌型添加测试覆盖。

### 阶段 3：小程序 MVP

- 构建牌桌局况设置界面。
- 构建牌面确认界面。
- 构建和牌条件选择界面。
- 构建结果展示界面。
- 集成算点引擎。

### 阶段 4：拍照识别辅助

- 添加拍照或上传图片入口。
- 从和牌照片中识别牌面。
- 在有价值的地方展示识别置信度。
- 允许用户快速修正识别错误的牌。
- 保留手动录入作为兜底方案。

### 阶段 5：打磨和验证

- 使用真实线下牌桌照片进行测试。
- 改善不够清晰的算点解释。
- 优化手机单手操作体验。
- 为“会打牌但不熟悉算点”的用户补充轻量引导。
- 使用常见日麻算点示例进行校验。

## 第一版非目标

- 三人麻将。
- 只靠一张照片全自动算点。
- 自动识别点棒。
- 完整牌谱记录或回放。
- 联机多人同步。
- 自定义地方规则引擎。

## 待确认问题

- 第一版应采用哪一套默认规则？
- 是否默认启用切上满贯？
- MVP 是否支持多倍役满和累计役满？
- 在拍照识别足够可靠之前，手动录入需要做到什么程度？
- 是否要求输入各家当前点数，还是只展示本次支付变化？
- 第一版界面只支持中文，还是同时支持中文和日文术语？

## 跟踪备注

- 优先保证算点正确和解释透明，而不是追求完全自动化。
- 将拍照识别视为辅助输入方式，而不是最终事实来源。
- 算点引擎应独立于小程序 UI。
- 使用模拟麻将桌视图降低表单操作成本，并让玩家方位更直观。
