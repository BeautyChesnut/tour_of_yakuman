# 立直麻将算点规则文档

本文档用于指导微信小程序的前端算点实现。MVP 以四人立直麻将为基础，当前本地算点已扩展三人麻将、多人荣和与部分役满包牌；在线房间仍按四人麻将运行。

## 规则定位

当前实现不是完整赛事规则引擎，而是一个覆盖常见四麻、三麻单局结算的手动算点工具。

### 默认规则建议

- 规则类型：本地算点可选择四人或三人立直麻将；在线房间固定为四人麻将。
- 食断：开启。
- 后付：允许。
- 赤宝牌：开启，支持赤五万、赤五筒、赤五索。
- 宝牌：开启。
- 杠宝牌：开启，由用户手动输入杠宝牌指示牌。
- 里宝牌：仅立直后开启，由用户手动输入里宝牌指示牌。
- 切上满贯：第一版默认关闭，暂不支持开启。
- 累计役满：默认开启，13 番以上按累计役满处理。
- 多倍役满：默认开启。
- 包牌：支持大三元、大四喜和四杠子的责任支付；复合役满仅对对应役满部分应用包牌。
- 双响、三响：采用雀魂规则，允许多人荣和，积棒和供托上家取り。
- 流局：支持荒牌流局和听牌罚符；途中流局、错和暂不处理。
- 终局排名、马点、返点、精算：第一版暂不处理。

### 三人麻将规则

- 使用东、南、西三个座位，默认起始点数为 35000 点。
- 二万至八万及赤五万不可用；一万、九万仍可正常输入。
- 北牌可以作为普通字牌输入，也可以按拔北宝牌计番；拔北本身不构成起和役。
- 不允许吃牌，允许碰、明杠、暗杠和加杠。
- 支持拔北岭上和抢北场景，分别复用岭上开花与抢杠的场面条件。
- 自摸、本场、荒牌流局和点差只在三名有效玩家之间结算。

### 包牌责任支付

- 责任者由用户手动指定，仅在和牌结果包含大三元、大四喜或四杠子时生效。
- 自摸时，责任者承担产生包牌的役满部分全部支付。
- 荣和时若责任者就是放铳者，由其承担该役满部分；若责任者与放铳者不同，双方各承担该役满部分的一半并分别向上取整到百点。
- 复合役满中不产生包牌的其他役满部分仍按普通荣和或自摸方式结算。

## 输入模型

### 牌表示

推荐内部使用稳定的英文编码，界面显示中文或日文术语。

| 类型 | 编码示例 | 含义 |
| --- | --- | --- |
| 万子 | `1m` - `9m` | 一万到九万 |
| 筒子 | `1p` - `9p` | 一筒到九筒 |
| 索子 | `1s` - `9s` | 一索到九索 |
| 风牌 | `east` `south` `west` `north` | 东南西北 |
| 三元牌 | `white` `green` `red` | 白发中 |
| 赤宝牌 | `red5m` `red5p` `red5s` | 赤五万、赤五筒、赤五索 |

赤宝牌在牌型判断时等同于普通 5，在宝牌计算时额外计 1 番。

### 本局输入

```ts
type RoundInput = {
  roundWind: "east" | "south" | "west" | "north";
  honba: number;
  riichiSticks: number;
  dealer: Seat;
  winner: Seat;
  discarder?: Seat;
  winType: "ron" | "tsumo";
  playerCount?: 3 | 4;
  playerPoints?: Record<Seat, number>;
};
```

### 手牌输入

```ts
type HandInput = {
  concealedTiles: Tile[];
  winningTile: Tile;
  melds: Meld[];
  doraIndicators: Tile[];
  kanDoraIndicators: Tile[];
  uraDoraIndicators: Tile[];
  nukiDoraCount?: number;
  liabilitySeat?: Seat;
  conditions: WinConditions;
};
```

`concealedTiles` 建议表示和牌前手内的牌，不包含 `winningTile`。副露和杠牌统一放入 `melds`。算点前需要将输入归一化成完整和牌结构。

### 副露表示

```ts
type Meld = {
  type: "chi" | "pon" | "minkan" | "ankan" | "kakan";
  tiles: Tile[];
  calledTile?: Tile;
  from?: Seat;
};
```

第一版如果不需要精确展示来源，可以先只要求 `type` 和 `tiles`。但暗刻、明刻、自摸、荣和会影响符数，因此至少要区分明副露和暗杠。

### 和牌条件

```ts
type WinConditions = {
  riichi: boolean;
  doubleRiichi: boolean;
  ippatsu: boolean;
  menzenTsumo: boolean;
  haitei: boolean;
  houtei: boolean;
  rinshan: boolean;
  chankan: boolean;
  tenhou: boolean;
  chiihou: boolean;
  enableUraDora: boolean;
};
```

部分条件可以由牌面推导，但第一版允许用户手动指定，以降低实现复杂度。

## 算点流程

```text
输入校验
  -> 和牌型拆解
  -> 役种判断
  -> 宝牌计算
  -> 番数合计
  -> 符数计算
  -> 基本点计算
  -> 各家支付计算
  -> 本场和供托调整
  -> 更新各家点数和点差
```

## 输入校验

第一版至少需要校验：

- 所有牌总数合理。
- 同一种非赤牌加赤牌折算后最多 4 张。
- 赤五万、赤五筒、赤五索各自最多 1 张，除非规则配置允许更多。
- `ron` 必须指定放铳者。
- `tsumo` 不应指定放铳者。
- 和牌者、亲家、放铳者不能产生冲突。
- 有立直或两立直时才允许里宝牌生效。
- 一发必须依附立直或两立直。
- 两立直不与普通立直重复计番。
- 天和仅亲家自摸。
- 地和仅子家自摸。
- 海底和岭上不同时成立。
- 河底和抢杠不同时成立。

## 役种判断

第一版应支持常见役种，并在结果中展示役种名称、番数、是否门清限定。

### 1 番役

| 役种 | 门清限定 | 副露番数 | 说明 |
| --- | --- | --- | --- |
| 立直 | 是 | 不可副露 | 用户指定 |
| 一发 | 是 | 不可副露 | 必须已立直 |
| 门前清自摸和 | 是 | 不可副露 | 门清自摸 |
| 平和 | 是 | 不可副露 | 四顺子、无役牌雀头、两面听 |
| 一杯口 | 是 | 不可副露 | 同色同数两组顺子 |
| 断幺九 | 否 | 1 | 全部为 2-8 的数牌 |
| 役牌 | 否 | 1 | 三元牌、场风、自风刻子或杠子 |
| 抢杠 | 否 | 1 | 用户指定 |
| 岭上开花 | 否 | 1 | 用户指定 |
| 海底摸月 | 否 | 1 | 用户指定 |
| 河底捞鱼 | 否 | 1 | 用户指定 |

### 2 番役

| 役种 | 门清番数 | 副露番数 | 说明 |
| --- | --- | --- | --- |
| 两立直 | 2 | 不可副露 | 不与立直叠加 |
| 七对子 | 2 | 不可副露 | 固定 25 符 |
| 一气通贯 | 2 | 1 | 同色 123、456、789 |
| 三色同顺 | 2 | 1 | 三门同数字顺子 |
| 混全带幺九 | 2 | 1 | 每组含幺九或字牌，且有顺子 |
| 对对和 | 2 | 2 | 四组刻子或杠子 |
| 三暗刻 | 2 | 2 | 三组暗刻或暗杠 |
| 三杠子 | 2 | 2 | 三组杠子 |
| 三色同刻 | 2 | 2 | 三门同数字刻子或杠子 |
| 小三元 | 2 | 2 | 两组三元刻子或杠子，加一组三元雀头 |
| 混老头 | 2 | 2 | 全部由幺九牌和字牌组成，通常还会叠加对对和或七对子 |

### 3 番以上役

| 役种 | 门清番数 | 副露番数 | 说明 |
| --- | --- | --- | --- |
| 二杯口 | 3 | 不可副露 | 两组一杯口，不与一杯口叠加 |
| 混一色 | 3 | 2 | 一门数牌加字牌 |
| 纯全带幺九 | 3 | 2 | 每组含幺九牌，无字牌，且有顺子 |
| 清一色 | 6 | 5 | 全部为同一门数牌 |

### 役满

第一版建议支持以下役满：

- 国士无双。
- 四暗刻。
- 大三元。
- 小四喜。
- 大四喜。
- 字一色。
- 绿一色。
- 清老头。
- 四杠子。
- 九莲宝灯。
- 天和。
- 地和。

双倍役满规则先做成配置项。第一版可以先按单倍役满计算，再在结果中保留扩展字段。

### 宝牌

宝牌、赤宝牌、杠宝牌、里宝牌只增加番数，不构成起和役。也就是说，只有宝牌而没有任何役种时，不能和牌。

宝牌指示牌规则：

- 数牌指示牌按 1 到 9 循环，例如 `3m` 指示 `4m`，`9m` 指示 `1m`。
- 风牌顺序：东 -> 南 -> 西 -> 北 -> 东。
- 三元牌顺序：白 -> 发 -> 中 -> 白。
- 赤五按普通 5 判断是否命中宝牌，同时额外计算赤宝牌。

## 符数计算

非七对子手牌从 20 符开始，累计后向上取整到 10 符。七对子固定 25 符，不再加其他符。

### 基础符

| 项目 | 符数 |
| --- | --- |
| 副底 | 20 |
| 门前荣和 | 10 |
| 自摸 | 2 |
| 七对子 | 固定 25 |

平和自摸按 20 符处理，不额外加自摸 2 符。平和荣和通常为 30 符，因为门前荣和加 10 符。

### 面子符

| 面子 | 中张牌 | 幺九牌或字牌 |
| --- | --- | --- |
| 明刻 | 2 | 4 |
| 暗刻 | 4 | 8 |
| 明杠 | 8 | 16 |
| 暗杠 | 16 | 32 |
| 顺子 | 0 | 0 |

荣和时，如果和牌张完成刻子，该刻子按明刻计算。自摸时，如果和牌张完成刻子，该刻子按暗刻计算。

### 雀头符

| 雀头 | 符数 |
| --- | --- |
| 三元牌雀头 | 2 |
| 场风雀头 | 2 |
| 自风雀头 | 2 |
| 双风雀头 | 规则配置，常见取 4 或 2 |

双风雀头存在规则差异，建议在规则配置中显式保存。

### 听牌符

| 听牌形 | 符数 |
| --- | --- |
| 边张 | 2 |
| 嵌张 | 2 |
| 单骑 | 2 |
| 两面 | 0 |
| 双碰 | 0 |

同一手牌只选择和牌张实际完成形对应的一种听牌符。

### 特殊情况

- 开放平和形荣和通常按 30 符处理，实作上可给 2 符后再进位。
- 七对子固定 25 符，不进位到 30 符。
- 役满不需要计算符数。
- 满贯及以上不需要展示符数用于点数，但仍可展示识别出的符数明细作为解释。

## 番数和限制牌

先计算役种番数，再加入宝牌番数。

| 牌值 | 条件 | 基本点 |
| --- | --- | --- |
| 满贯 | 5 番，或 4 番 40 符以上，或 3 番 70 符以上 | 2000 |
| 跳满 | 6-7 番 | 3000 |
| 倍满 | 8-10 番 | 4000 |
| 三倍满 | 11-12 番 | 6000 |
| 役满 | 役满，或规则允许时 13 番以上累计役满 | 8000 |

如果开启切上满贯，则 4 番 30 符和 3 番 60 符按满贯计算。

## 基本点公式

非限制牌使用：

```text
基本点 = 符数 * 2 ^ (番数 + 2)
```

若计算出的基本点超过 2000，则按满贯基本点 2000 处理。

## 支付计算

所有单人支付金额向上取整到 100 点。

### 子家荣和

```text
放铳者支付 = ceil100(基本点 * 4)
```

### 亲家荣和

```text
放铳者支付 = ceil100(基本点 * 6)
```

### 子家自摸

```text
亲家支付 = ceil100(基本点 * 2)
其他子家支付 = ceil100(基本点)
```

结果常写作：

```text
子家支付 / 亲家支付
```

例如 `1000 / 2000` 表示其他子家各付 1000，亲家付 2000。

### 亲家自摸

```text
每个子家支付 = ceil100(基本点 * 2)
```

结果常写作：

```text
全部支付
```

例如 `4000 all` 表示三名子家各付 4000。

## 本场和供托

### 本场

每一本场给和牌者额外增加 300 点总收入：

- 荣和：放铳者额外支付 `本场数 * 300`。
- 自摸：每名对手额外支付 `本场数 * 100`。

### 立直供托

每根立直棒 1000 点：

- 单人和牌时，全部供托归和牌者。
- 双响、三响采用雀魂规则：积棒和供托均上家取り，全部归离放铳者最近的和牌者。

上家取り的优先顺序按放铳者之后的摸牌顺序计算：

| 放铳者 | 优先和牌者顺序 |
| --- | --- |
| 东 | 南 > 西 > 北 |
| 南 | 西 > 北 > 东 |
| 西 | 北 > 东 > 南 |
| 北 | 东 > 南 > 西 |

多人荣和时，每个和牌者仍分别从放铳者处获得自己的荣和点数；若和牌者中包含亲家，则连庄。

如果小程序记录的是“当前桌面可见点数”，立直棒通常已经从立直者点数中扣除，此时结算时只需要把供托加给和牌者。如果只是输入供托数量但没有记录是谁立直，则点数变化展示会以“供托池转入和牌者”的方式呈现。

## 点数结算和点差

### 点数变化

```text
玩家结算后点数 = 玩家结算前点数 + 本局点数变化
```

本局点数变化包括：

- 荣和或自摸支付。
- 本场加点。
- 立直供托收入。

### 点差展示

第一版建议至少展示：

- 每家结算前点数。
- 每家本局变化，例如 `+3900`、`-3900`。
- 每家结算后点数。
- 当前用户与其他三家的点差。
- 当前排名和与上一名、下一名的点差。

### 局势分析附加推演

四麻与本地三麻局势分析在正式结算规则之上提供以下假设推演：

- 牌局阶段：东场视为前半场，南一至南三视为后半场，南四标记为默认半庄终局，西场和北场标记为延长局。实际终局仍以现场规则为准。
- 立直成本：只模拟当前视角支付 1000 点后的即时点数、顺位和供托变化，不预测和率或后续牌局结果。
- 荒牌流局：由用户手动指定四家听牌状态，复用正式听牌罚符规则计算结算后点数；庄家听牌则标记连庄，本场增加一，供托保留。
- 同点顺位：局势分析统一使用东、南、西、北作为稳定破平顺序。该顺序只用于本工具展示，不代表所有平台的终局排名规则。

三麻局势分析沿用相同能力，但只使用东、南、西三席：

- 目标与风险：展示升至第一、第二位的最低条件，以及跌至第三位的最低放铳风险线；北家不参与排名或结果。
- 自摸支付：只计算两名对手的支付，不采用北家补偿规则；本场由两名对手各支付 100 点。
- 牌局阶段：南三局标记为默认半庄终局，西场和北场仍标记为延长局。
- 荒牌流局：复用正式三麻 3000 点听牌罚符，一家听牌时两名未听者各支付 1500 点，两家听牌时未听者合计支付 3000 点。
- 同点顺位：按东、南、西作为稳定破平顺序。该顺序仍只用于本工具展示。

局势分析不会自动判断手牌是否听牌，也不会结合巡目、牌河或对手行为生成攻防概率。

### 后退修改

每一局结算需要保留输入快照：

```ts
type SettlementSnapshot = {
  roundInput: RoundInput;
  handInput: HandInput;
  result: ScoringResult;
};
```

用户从结果页返回时恢复 `roundInput` 和 `handInput`，重新确认后覆盖当前这局的 `result`。

## 推荐返回结果

```ts
type ScoringResult = {
  valid: boolean;
  errors: string[];
  yaku: Array<{ name: string; han: number }>;
  dora: Array<{ name: string; han: number }>;
  han: number;
  fu?: number;
  fuDetails: Array<{ name: string; fu: number }>;
  limit?: "mangan" | "haneman" | "baiman" | "sanbaiman" | "yakuman";
  basePoints: number;
  payments: Array<{
    from: Seat;
    to: Seat;
    points: number;
    reason: "hand" | "honba" | "riichi-stick";
  }>;
  pointDelta: Record<Seat, number>;
  pointsAfter?: Record<Seat, number>;
  pointDiffs?: Record<Seat, Record<Seat, number>>;
};
```

## 当前实现边界

当前已实现：

- 四人麻将与本地三人麻将。
- 标准四面子一雀头。
- 七对子。
- 国士无双。
- 常见 1-6 番役。
- 常见役满。
- 宝牌、赤宝牌、杠宝牌、里宝牌。
- 荣和、自摸、本场、供托。
- 荒牌流局与听牌罚符。
- 单一和牌者结算与双响、三响多人荣和结算。
- 大三元、大四喜和四杠子的责任支付。
- 三麻拔北、拔北岭上、抢北和禁吃规则。

当前暂不实现：

- 上述三种役满之外的地方包牌规则。
- 途中流局。
- 终局马点、返点、排名分。
- 在线三麻房间。
- 复杂地方役。
